# MAQDAR roadmap

Multi-tenant cloud SaaS for service parts planning in the Middle East. Target: Syncron Service Parts Planning parity, then differentiators for the region.

## Phases

**Phase 0, Foundations:** repo, CI, Supabase link, synthetic data.

**Phase 1, Platform core:** tenancy and auth, design system (English first, RTL-ready), master data, import wizard, REST API, audit log.

**Phase 2, Forecasting and inventory policy:** engine worker on pgmq; demand classification (ADI and CV squared, ABC-XYZ, lifecycle); forecast models (Croston, SBA, TSB, ETS, ARIMA, bootstrap) chosen per item-location by rolling backtest; Hijri events (Ramadan, Eid, Hajj) and summer heat as seasonal effects; supersession and interchange roll-up; service-level policies with safety stock, reorder point and max; planner workbench with overrides; KPI dashboards (availability, fill rate, inventory value, excess, obsolete, forecast accuracy).

**Phase 3, Replenishment:** purchase suggestions with MOQ, pack size, container fill, supplier calendars and country weekends; approval rules with auto-confirm; redistribution and allocation; export to ERP by API, webhook or sFTP; planned events (campaigns, recalls, tenders); excess and obsolescence actions; nearest-stock item locator.

**Phase 4, Advanced optimization (Syncron parity):** multi-echelon inventory optimization; simulation center that replays history against alternative policies; causal forecasting from external drivers; installed-base forecasting; virtual regional stocking and dealer-as-depot; supplier portal; dealer returns.

**Phase 5, Differentiators:** AI planning copilot using the Claude API over read-only, tenant-scoped views (English, Arabic optional); parts pricing; multi-source and parallel-import sourcing; ZATCA and UAE e-invoicing through certified providers; WhatsApp and email alerts; installable mobile web app for branches; ERP connectors (SAP, Dynamics 365, Oracle, Odoo).

**Phase 6, Production:** self-hosted in-region deployment option from the same code, security hardening, load testing at 500,000 items and 200 locations, billing and onboarding, compliance documentation.

| 2026-10-09 | Global reference tables without `organization_id`                                         | Countries, currencies, Ramadan/Eid windows and public holidays are regional facts, not business data: select-only, written by migrations, seeded from the engine's curated CSVs. Per-organization overrides arrive in Step 4.          |
| 2026-10-09 | Composite tenant foreign keys on master data                                              | `unique (organization_id, id)` on parents and `(organization_id, child_id)` foreign keys make cross-tenant references impossible by construction; pgTAP proves it.                                                                     |
| 2026-10-09 | `demand_history` has no foreign keys                                                      | Per-row constraint triggers cost ~0.2 ms per row (a 20 M-row load would take hours). The import path validates references and runs a set-based anti-join after loading; `organization_id` leads the primary key and every policy.      |
| 2026-10-09 | `demand_date` is a `date` (business day at the location)                                  | Weekend and holiday effects line up with the location calendar; instants would shift days across time zones. Timestamps elsewhere stay `timestamptz` UTC.                                                                              |
| 2026-10-09 | Hand-curated Gulf calendar instead of the `holidays`/`hijridate` packages                 | Aggregators and libraries were wrong on a dozen observed dates in the window (Oman's one-day lags, decreed shifts); every row carries its source and a coverage check refuses windows outside the verified range.                      |
| 2026-10-09 | polars 1.44.2 and numpy 2.5.3 pinned; polars 2.0 deferred                                 | polars 2.0.0 was three days old; the generator uses only eager APIs that exist in both. numpy changed its binomial sampler in 2.5, so the pin is what makes bundles reproducible.                                                      |
| 2026-10-09 | Deterministic uuid5 ids for synthetic organizations and rows                              | The loader derives every id from the organization and the natural key, so reloads are idempotent and tests can predict ids without reading the database.                                                                               |
