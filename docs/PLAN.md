## Phases

**Phase 0, Foundations:** repo, CI, Supabase link, synthetic data.

**Phase 1, Platform core:** tenancy and auth, design system (English first, RTL-ready), master data, import wizard, REST API, audit log.

**Phase 2, Forecasting and inventory policy:** engine worker on pgmq; demand classification (ADI and CV squared, ABC-XYZ, lifecycle); forecast models (Croston, SBA, TSB, ETS, ARIMA, bootstrap) chosen per item-location by rolling backtest; Hijri events (Ramadan, Eid, Hajj) and summer heat as seasonal effects; supersession and interchange roll-up; service-level policies with safety stock, reorder point and max; planner workbench with overrides; KPI dashboards (availability, fill rate, inventory value, excess, obsolete, forecast accuracy).

**Phase 3, Replenishment:** purchase suggestions with MOQ, pack size, container fill, supplier calendars and country weekends; approval rules with auto-confirm; redistribution and allocation; export to ERP by API, webhook or sFTP; planned events (campaigns, recalls, tenders); excess and obsolescence actions; nearest-stock item locator.

**Phase 4, Advanced optimization (Syncron parity):** multi-echelon inventory optimization; simulation center that replays history against alternative policies; causal forecasting from external drivers; installed-base forecasting; virtual regional stocking and dealer-as-depot; supplier portal; dealer returns.

**Phase 5, Differentiators:** AI planning copilot using the Claude API over read-only, tenant-scoped views (English, Arabic optional); parts pricing; multi-source and parallel-import sourcing; ZATCA and UAE e-invoicing through certified providers; WhatsApp and email alerts; installable mobile web app for branches; ERP connectors (SAP, Dynamics 365, Oracle, Odoo).

**Phase 6, Production:** self-hosted in-region deployment option from the same code, security hardening, load testing at 500,000 items and 200 locations, billing and onboarding, compliance documentation.

Use a new explicit organization-wide `transfer_handoffs:read` permission issued only by owners/admins. Existing keys gain no scope; expiry, revocation and creator-role checks remain enforced. Browser users retain both-location access requirements. Transmission, acknowledgements, reservations and transfer-order creation follow separately. See [transfer-handoff-read-api.md](transfer-handoff-read-api.md).
